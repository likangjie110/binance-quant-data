# 核心信念（本项目的裁决依据）

> 当"该不该这么做"出现分歧时，回到这份文件，而不是回到聊天记录。
> 每条都配了本项目的具体含义；无具体含义的空话已删除。

## 一、数据与证据

1. **证据优先于记忆**：接口行为、路由、字段以实测/官方文档/打包产物为准；"我记得"不算证据。
   本项目所有数据源结论都附文件:行或 HTTP 证据（见 `币安数据源分析报告.md`）。
2. **原始数据是权威**：落库必须保留原始事件（`stream_events.raw`）；派生表可重建，原始事件不可重建。
3. **静默不等于正常**：WS "握手成功但 0 帧" 是失败（合约旧路由即如此），必须有看门狗与可观测心跳。
4. **先复现，再修复**：任何 bug 修复都要有复现脚本或失败用例；修完复现脚本应反转退出码。
   （范例：`scripts/analysis/repro_thread_safety.py`，TD-RUNTIME-001。）

## 二、边界与安全

5. **只读是产品边界**：不写下单/撤单/划转/提币代码；私有 Key 只用于查询与订阅。
6. **密钥只存在于进程环境与内存**：不打印、不入库、不进日志；连接串同理（TD-SEC-001 待修）。
7. **私有数据默认不可信环境**：`work/` 含 App 配置与 Cookie 副本，永远本地保留、不进版本库（D3）。
8. **外部输入在边界解析**：交易所 JSON 只在 `normalize()` 解析一次；下游不读裸字段。

## 三、工程纪律

9. **核心零依赖**：`tools/` 只用标准库；可选能力（PostgreSQL）以 extras 形式存在，不得变成必需。
10. **重构不改行为，行为变更单独提交**：纯重构与 bug 修复分开；每批有回滚方案。
11. **单写线程**：DB 连接与信号状态只允许一个写线程持有；先修这个再谈吞吐（TD-RUNTIME-001/002）。
12. **幂等优先**：同一条事件处理两次只产生一份结果（orders upsert / fills 去重 / events 追加）。
13. **上下文是稀缺资源**：`AGENTS.md` 只做地图（≤100 行），细节下推到 `docs/`；不写教程式长文。
14. **强制不变量，不微观管理**：能机械检查的（链接、行数、DDL 一致性、密钥扫描）交给脚本/CI。
15. **交互式决策必须落盘**：确认过但没写进仓库的决策等于没做（见 `decisions.md`）。
16. **文档随代码同提交**：行为变化必须同步更新对应文档；文档断链由 `check_docs.py` 拦截。

## 四、改造方法

17. **人掌舵，智能体执行**：计划先经人确认，再动代码；阶段 1 的扫描结论必须可复跑。
18. **小步高频还债**：技术债按批次偿还，每批有独立验收与回滚；不搞一次性大重构。
19. **发现即登记**：扫描阶段不顺手修 bug；新问题先写进 `tech-debt-tracker.md` 再排期。
20. **把规则提升为代码**：反复出现的口头规则（如"不要打印密钥"）最终要变成扫描器/门禁。
